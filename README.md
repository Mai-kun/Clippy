# Clippy

Сверхлёгкий рекордер instant replay для Windows. Аналог ShadowPlay и Medal — только
без установки, без игровых оверлеев и без фоновой службы.

**Запустил — и он уже пишет.** Не нужно ни разбираться в ключах, ни создавать конфиг: положите
`Clippy.exe` и нажмите. Дальше всё делают F8 и F9.

Собран как **Native AOT**: один `.exe` около 9 МБ, без .NET на компьютере, без среды
выполнения. Запускается за десятки миллисекунд и не ест память на фоне.

---

## Быстрый старт

Есть два способа:

- **Установщик** — `Clippy-Setup.exe`. Ставит Clippy, ярлык на рабочий стол, автозапуск и
  сообщает об обновлениях. Всё внутри, настраивать нечего.
- **Портативный архив** — `Clippy-win-x64.zip`. Распакуйте в любую папку и запустите `Clippy.exe`.

`ffmpeg.exe` не вкладывается в поставку: благодаря аппаратному NVENC и Media Foundation,
Clippy работает из коробки без внешних зависимостей (размер архива всего ~8 МБ).
Если вам нужен фолбэк на ffmpeg, положите `ffmpeg.exe` рядом или добавьте в PATH. `clippy_nvenc.dll` уже на месте.

### Через Winget

```powershell
winget install Mai-kun.Clippy
```

Менеджер пакетов Windows сам скачает установщик, поставит Clippy для текущего пользователя
и будет обновлять при выходе новых версий. Обновление вручную: `winget upgrade Mai-kun.Clippy`.
Удаление: `winget uninstall Mai-kun.Clippy`.

Появится окно консоли с логом и иконка в трее. Дальше работайте в играх — нажмите **F8** сразу
после яркого момента, и последние 30 секунд окажутся в файле.

Завершение: правый клик по иконке в трее → **Exit**.

### Горячие клавиши

| Клавиша | Что делает | По умолчанию |
|---|---|---|
| **F8** | сохранить короткий клип | 30 секунд |
| **F9** | сохранить длинный клип | 3 минуты |

Клавиши меняются в `config.json`. Обе работают, пока запущен `Clippy.exe`, и не требуют фокуса
в приложении — это глобальные хоткеи.

После сохранения Clippy играет короткий звук и показывает системное уведомление Windows
с именем файла. Системное уведомление дублирует звук, а не заменяет его: звук слышно, когда вы
смотрите на экран, уведомление — когда вы переключились.

## Настройки: `config.json`

Рядом с `Clippy.exe` лежит `config.example.json` — **покомментированный** образец. Скопируйте
его в `config.json` и правьте. Комментарии и висячие запятые разрешены, файл можно читать
человеком.

| Поле | По умолчанию | Смысл |
|---|---|---|
| `OutputFolder` | `clips` | Папка для клипов, считается от папки с exe, а не от рабочего каталога |
| `LogsFolder` | `logs` | Папка для логов и таймингов; при старте остаются 10 самых свежих |
| `ShortClipSeconds` | `30` | Длительность клипа по F8 |
| `LongClipSeconds` | `180` | Длительность клипа по F9 |
| `ShortClipHotkey` | `F8` | Клавиша короткого клипа (F1–F24) |
| `LongClipHotkey` | `F9` | Клавиша длинного клипа |
| `PlaySoundNotification` | `true` | Звук после сохранения |
| `StartMinimizedToTray` | `false` | Запуск сразу без окна консоли |
| `CheckForUpdates` | `true` | Проверка новых версий при старте (один запрос к GitHub) |
| `VideoEncoder` | `nvenc_direct` | Кодек: `nvenc_direct` / `h264_nvenc` / `h264_qsv` / `h264_amf` / `libx264` |
| `VideoBitrateMbps` | `6` | Битрейт для NVENC, диапазон 2–50 |
| `MaxClipsFolderSizeGB` | `0` | Потолок на папку с клипами, ГБ. 0 = без ограничения. Допустимо 0/10/20/30/50 |
| `AudioEncoder` | `media_foundation` | `media_foundation` (AAC средствами Windows) / `ffmpeg` |

Значение вне диапазона молча заменяется на безопасное, и файл всё равно работает: опечатка в
конфиге не должна мешать записи.

### Про клипы и диск

Клипы накапливаются незаметно, и папка растёт, пока что-то не падает на заполненном диске. Чтобы
это перестало быть сюрпризом, у папки есть потолок: **Clips Storage Limit** в трее или поле
`MaxClipsFolderSizeGB` в конфиге.

Действует так: после каждого сохранения **и** при запуске папка пересчитывается, и если она больше
квоты, самые старые клипы удаляются по дате создания, пока не уложится. Считаются и удаляются
только `*.mp4` — в папке могут лежать ваши собственные файлы, и молча удалять их ради квоты видео
недопустимо.

По умолчанию лимита нет (`0`). Квота, удаляющая файлы без явного разрешения, — опасное значение
для дефолта, поэтому включать его нужно руками.

Клип сохраняется **только** по горячей клавише или по `--export-at`. При выходе из приложения —
Exit в трее, закрытие окна, Ctrl+C — Clippy не пишет ничего: выход это выход, а не повод создать
файл, о котором никто не просил. Режим `--record N` исключение: там файл и есть смысл запуска.
### Про память и битрейт

Clippy непрерывно держит историю за последние 190 секунд — именно поэтому клип можно сохранить
задним числом. Хранилище двухуровневое: в RAM лежит только **голова** последних 32 секунд
(кольцевой буфер, **уже закодированный** видеопоток), а всё, что из неё вытесняется, уходит в
**дисковый хвост** — временные сегменты по 45 секунд в `%TEMP%\Clippy\spool`. Папка очищается при
старте и при выходе. Поэтому память теперь определяется 32 секундами видео, а не 190:

| `VideoBitrateMbps` | RAM-голова (32 с) |
|---|---|
| 12 | ~40 МБ |
| 8 | ~27 МБ |
| 6 (по умолчанию) | ~20 МБ |
| 4 | ~13 МБ |

Дисковый хвост держит ещё ~158 секунд (с точностью до одного сегмента) и на RAM не влияет: клип
короче 32 секунд (F8, это 30 секунд) собирается целиком из оперативной памяти, длинный (F9) —
склеивается из 32 секунд RAM и недостающих ~148 секунд с диска.

Битрейт — это **цель**, а не потолок. На насыщенном рабочем столе 1080p фактический поток выходит
выше заданного: замер `nvenc_direct` на 20 секундах дал 8.3 Мбит/с при запросе 6, а `h264_nvenc`
на том же контенте — 19.2. Если память важнее качества, занижайте.

На программном кодировщике `libx264` эта настройка **не действует**: там качество задаёт CRF,
а не целевой битрейт.

### Про кодек (H.265 / HEVC)

`VideoCodec` в конфиге (и подменю **Video Codec** в трее) выбирает кодек: `hevc` (по умолчанию)
или `h264`. Учитывается он прямым мостиком NVENC (`VideoEncoder = "nvenc_direct"`) — только он
может попросить у драйвера `NV_ENC_CODEC_HEVC_GUID`. Кодировщики через ffmpeg всегда дают H.264,
и муксер смотрит на байты, а не на настройку: клип пишется как `hvc1`/`hvcC` только тогда, когда
кодировщик действительно отдал VPS, поэтому откат на ffmpeg даст корректный H.264-файл.

Замер на одной и той же записи 1080p (2×3.5-минутных клипа, полный декод через ffmpeg, 0 ошибок):

| Кодек / битрейт | F8, 30 с | F9, 180 с |
|---|---|---|
| H.264, 6 Мбит/с | 20.4 МБ | 120.3 МБ |
| HEVC, 6 Мбит/с | 18.4 МБ | 109.3 МБ |
| **HEVC, 3 Мбит/с** | **10.9 МБ** | **60.9 МБ** |

При том же битрейте HEVC даёт заметно больше деталей на бит, поэтому та же картинка переносится на
вдвое меньший битрейт: RAM-голова (32 с) с ~20 МБ становится ~12 МБ, трёхминутный клип — вдвое
меньше. Цена — более строгая совместимость: H.264 для широкого набора плееров и редакторов.

## Трей-меню

Правый клик по иконке:

| Пункт | Действие |
|---|---|
| **Open clips folder** | открыть папку с готовыми клипами |
| **Open Last Clip** | открыть самый свежий клип в программе, назначенной для `.mp4` |
| **Open config.json** | открыть конфиг в текстовом редакторе |
| **Short Clip Duration** | 15 / 30 / 60 секунд — длина клипа по F8 |
| **Long Clip Duration** | 1 / 2 / 3 / 5 минут — длина клипа по F9 |
| **Video Bitrate / RAM** | 2 / 4 / 6 / 8 / 12 / 16 / 20 / 25 / 30 / 50 Мбит/с, рядом показана оценка расхода памяти |
| **Video Encoder** | `nvenc_direct`, `h264_nvenc` или `libx264` |
| **Hotkeys** | `F8/F9` (по умолчанию), `F9/F10` или `F11/F12` |
| **Select Clips Folder...** | выбрать папку для клипов системным диалогом |
| **Clips Storage Limit** | Unlimited / 10 / 20 / 30 / 50 ГБ |
| **Show / Hide Log** | показать или скрыть окно консоли с логом |
| **Check for Updates** | проверить релиз на GitHub |
| **Restart** | перезапустить Clippy с теми же аргументами — нужно, чтобы применились кодировщик и битрейт |
| **Exit** | корректно завершить работу |

Пять подменю меняют настройки на лету: галочка переезжает на новое значение, файл `config.json`
переписывается, и следующий клип берёт уже его. Смена кодировщика и битрейта применяется со
следующей перезапуска записи, а не к текущей — для этого в трее есть **Restart**: он запускает
новый экземпляр с теми же аргументами и только потом завершает текущий, поэтому запись не
прерывается на время запуска. Если перезапуск не удался, Clippy остаётся работать и пишет об
ошибке в лог и во всплывающее уведомление.

Исчезновение иконки — это `Exit`. Clippy не сворачивается в фоновый режим незаметно: пока иконка
есть, запись идёт.

## Системные требования

- **Windows 10 2004 (сборка 19041) или новее, Windows 11**, x64. Более ранние сборки Windows 10
  не умеют убирать рамку захвата.
- **.NET не требуется** — это Native AOT, всё внутри exe.
- **ffmpeg** в своей папке или в `PATH` — уже лежит рядом. Нужен кодировщику `h264_nvenc`
  и программному `libx264`; на `nvenc_direct` не нужен вовсе.
- **clippy_nvenc.dll** рядом с exe — только для `nvenc_direct`. Без неё Clippy один раз
  напишет об этом в лог и продолжит через `h264_nvenc`.
- **Видеокарта**: NVIDIA даёт аппаратное кодирование через NVENC и почти не нагружает процессор.
  На Intel/AMD укажите `h264_qsv` / `h264_amf`, либо позвольте Clippy упасть на `libx264` —
  запись продолжится, но нагрузка на CPU вырастет.
- **Микрофон не нужен**: записывается системный звук (то, что слышно в наушниках/динамиках).

## Как это устроено

Clippy гибридный: звук и видео кодируются разными путями, и оба аппаратные.

- **Захват** — `Windows.Graphics.Capture` (WGC). Кадр приходит как текстура на GPU.
- **Видео, `nvenc_direct`** — текстура отдаётся в NVENC прямо там, где лежит, через
  `clippy_nvenc.dll`: ни копирования в системную память, ни процесса `ffmpeg`. Мостик написан на C
  поверх официального `nvEncodeAPI.h` — только потому, что каждая структура этого API определяет
  свою разметку номером версии внутри себя, и переписанная на C# копия расходилась бы с
  заголовком молча, а не с ошибкой компиляции.
- **Видео, `h264_nvenc`** — тот же NVENC, но через дочерний процесс `ffmpeg`: кадр читается в ОЗУ
  и уходит в его stdin. Медленнее, зато не требует DLL и годится для отладки.
- **Звук** — системный AAC через Windows Media Foundation, прямо внутри Clippy. Процесс `ffmpeg`
  для звука не нужен вообще.
- **MP4** собирается собственным муксером, без перекодирования: из буфера вырезаются нужные пакеты.
- Звук и видео сшиваются по **общему нулю времени** (`masterZero`) и выравниваются по
  ключевому кадру видео, поэтому рассинхрона в клипах нет.

### Ключи командной строки

Обычно они не нужны. Для диагностики:

| Ключ | Что делает |
|---|---|
| `--help`, `-h`, `--usage` | справка по флагам |
| `--record [секунды]` | запись в файл на фиксированное время |
| `--audio` | добавить системный звук к `--record` |
| `--hotkeys` | включить F8/F9 во время `--record` |
| `--tray`, `--minimized` | режим трея |
| `--encoder=ИМЯ` | кодек на один запуск, перекрывает конфиг |
| `--fps-mode=РЕЖИМ` | `passthrough` (по умолчанию) / `vfr` / `cfr` |
| `--export-at=С` `--export-dur=С` | вырезать клип во время записи |
| `--capture [секунды]` | захват без кодирования, для диагностики |
| `--smoke` | сквозная проверка |
| `--test-parsers`, `--test-ring`, `--test-mp4`, `--test-audio-timeline` | самотесты |
| `--test-nvenc-native` | прогнать 30 кадров через нативный NVENC и распарсить результат |

## Сборка из исходников

Два шага, и порядок важен: мостик должен существовать на диске **до** `dotnet publish`, иначе цель
копирования в `.csproj` не увидит файл и в релиз уйдёт exe без DLL.

```powershell
src\native\build.cmd
dotnet publish src/Clippy.csproj -c Release -r win-x64 -p:PublishAot=true -o publish
```

`build.cmd` сам находит Visual Studio через `vswhere` и собирает `clippy_nvenc.dll` рядом с исходниками;
`dotnet publish` кладёт её в `publish/`. Требуется Visual Studio 2022 Build Tools с компонентами C++
(линкер нужен и мостику, и AOT). Готовый `publish/Clippy.exe` самодостаточен.

> `build.cmd` и AOT-линкер оба ищут `vswhere` через `PATH`, а папка Visual Studio Installer там
> по умолчанию отсутствует. Скрипт правит это у себя, но если `dotnet publish` падает с
> «vswhere.exe is not recognized», добавьте её в `PATH` вручную.

## Релизы

Текущая версия — **1.3.5**.

Манифест для Winget лежит в [`winget/Mai-kun.Clippy.yaml`](winget/Mai-kun.Clippy.yaml). Это шаблон:
перед отправкой в `microsoft/winget-pkgs` нужно подставить настоящий SHA256 сборки
(`Get-FileHash .\Clippy-Setup.exe -Algorithm SHA256`) и поднять `PackageVersion`.

Каждый тег публикует два файла:

| Файл | Что это |
|---|---|
| `Clippy-Setup.exe` | установщик (Inno Setup): ярлыки, автозапуск, сообщения об обновлениях |
| `Clippy-win-x64.zip` | портативная папка: `Clippy.exe`, `ffmpeg.exe`, `clippy_nvenc.dll`, конфиг-образец |

Имя zip-архива менять нельзя: в уже установленных сборках обновлятор ищет именно его, и переименование
молча остановит автообновление у всех, кто уже обновлялся.

Обновление Clippy проверяет GitHub Releases при старте (один запрос, который без интернета просто
не приносит результата) и показывает системное уведомление. Установку запускает сам пользователь:
правый клик по иконке в трее → **Check for Updates**.
